# carelog — 개발 계획

육아 기록 앱. 수유 / 기저귀 / 수면을 빠르게 기록하고 오늘 요약을 본다.

## 개발 원칙: 기능별 세로 완성

화면을 전부 만든 뒤 DB를 붙이지 않는다. **기능 하나가 Today → SQLite → Records → 수정·삭제까지
전부 동작**하게 만든 뒤 다음 기능으로 넘어간다. 난이도 순서상 수유 → 기저귀 → 수면.

각 단계가 끝나면 변경사항 / 실행 방법 / 확인 항목을 보고하고 멈춘다.
사용자가 직접 실행해 확인한 뒤에만 다음 단계로 진행한다.

## 데이터 규칙

### 수유

| 필드 | 필수 | 비고 |
|---|---|---|
| 수유 시각 | 필수 | |
| 수유량(ml) | 선택 | |
| 메모 | 선택 | |
| 생성·수정 시각 | 내부 | 사용자에게 노출하지 않음 |

**수유량을 입력하지 않으면 `0`이 아니라 `NULL`로 저장한다.**
`0ml`과 `양을 기록하지 않은 수유`는 다른 사실이다.

- 빈 입력 → `NULL`
- 값을 입력하는 경우 → **0보다 큰 정수만** 허용
- `0` 입력 → **입력 오류로 거부한다**

`0ml` 기록을 허용하면 그것이 `마지막 수유` 시각을 갱신해, 이 앱에서 가장 중요한
숫자를 오염시킨다. "물렸지만 먹지 않음"은 수유와 다른 종류의 이벤트이고 V1 밖이다.

집계 표시도 같은 원칙을 따른다. 오늘 수유량이 한 번도 입력되지 않았다면
`총량 0ml`로 보여주지 말고 항목을 숨기거나 `기록 없음`으로 표시한다.

### 기저귀

종류(소변·대변·둘 다)는 필수다. 자유 문자열로 두면 오타가 조용히 저장되므로
DB 제약으로 세 값만 허용한다.

### 수면

수면은 시각이 아니라 **구간**이다.

- **종료 시각이 비어 있으면 "진행 중"이다.** 수유량 `NULL`과 같은 결로,
  "아직 안 끝남"과 "0분 잤음"은 다른 사실이다.
- **진행 중인 수면은 하나만 허용한다.** 앱에서 검사하고 DB 제약으로도 막는다.
- 종료 시각은 시작 시각보다 뒤여야 한다. 같은 시각도 허용하지 않는다.
- 1분 미만은 `0분`이 아니라 **`1분 미만`**으로 표시한다. 시작과 종료를 연달아
  누르면 실제로 생기는데, `0분`은 기록이 안 된 것처럼 읽힌다.
- 12시간 이상 진행 중이면 종료를 잊었을 가능성을 안내한다. 막거나 자동 종료하지는
  않는다 — 실제로 긴 수면도 있다.

### 시각과 날짜 저장

| 값 | 타입 | 이유 |
|---|---|---|
| 수유 시각 (`occurred_at`) | epoch milliseconds `INTEGER` | |
| 수면 시작·종료 | epoch milliseconds `INTEGER` | |
| 생성·수정 시각 | epoch milliseconds `INTEGER` | |
| 아이 생년월일 | `YYYY-MM-DD` `TEXT` | 특정 순간이 아니라 달력상의 날짜다. epoch로 저장하면 시간대가 바뀔 때 날짜가 밀린다 |

SQLite는 ISO 8601 문자열도 정상 지원한다. epoch milliseconds를 고르는 이유는 그것이
옳아서가 아니라, 이 앱이 정렬·범위 검색·두 시각의 차이 계산을 많이 하고
JS와 왕복 변환이 없기 때문이다.

주의: SQLite의 `unixepoch` 계열 함수는 **초 단위**다. 밀리초 값을 그대로 넘기면 안 된다.
날짜 경계는 JavaScript에서 계산하고 숫자 범위로 조회한다.

```sql
WHERE occurred_at >= ? AND occurred_at < ?
```

`occurred_at`에는 인덱스를 건다. 모든 조회가 이 컬럼의 범위 검색이다.

### "오늘"의 경계

**기기 현지 시간 기준 00:00 이상, 다음 날 00:00 미만.**

새벽 수유를 전날 육아 주기에 포함하는 방식도 가능하지만 "하루 시작 시각 설정"이라는
새 기능이 필요해진다. V1에는 과하다.

끝 시각을 `시작 + 86,400,000ms`로 계산하지 않는다. 서머타임 지역에서는 하루가 항상
24시간이 아니다. 현지 달력으로 오늘 자정과 다음 날 자정을 각각 만든 뒤 epoch로 변환한다.
(한국은 서머타임이 없어 실제로 깨지지 않지만, 비용이 없으므로 처음부터 맞게 쓴다.)

### 경과 시간 갱신

"마지막 수유 1시간 24분 전"은 화면을 열어둔 동안 멈춰 있으면 안 된다.

- 화면 표시 중 1분마다 갱신한다
- 백그라운드에서 foreground로 돌아오면 즉시 갱신한다
- 화면을 벗어나면 타이머를 정리한다
- 갱신할 때마다 SQLite를 다시 조회하지 않는다. 마지막 수유 시각만 들고 현재 시각만 갱신한다

### 입력 검증

- **빈 문자열 판정과 숫자 변환을 분리한다.** `Number('')`는 `0`이므로
  `Number(input) || null` 같은 코드는 빈 입력과 진짜 `0` 입력을 둘 다 `null`로 만든다.
- 미래 시각은 저장하지 않는다. 허용하면 "마지막 수유 -5분 전"이 나온다.

### Today 화면 표시 예

```
마지막 수유      1시간 24분 전
오늘 수유        5회
입력된 수유량    220ml
```

### 4단계 — Today 요약과 통계 ✅

수유 횟수·수유량·기저귀 횟수·마지막 수유 경과 시간은 1~3단계에서 이미 붙었다.
**이번에 새로 만드는 것은 오늘 수면시간 하나와 카드 배치 정리다.**

#### 오늘 수면시간

**수면 전체 길이를 더하면 안 된다.** 날짜 경계와 겹치는 구간만 집계한다.
수면은 구간이라 하루에 걸치는 경우가 흔하다.

```
전날 23:00 → 오늘 06:00
  전날 통계  1시간
  오늘 통계  6시간
```

```
겹치는 구간 = max(0, min(종료 ?? now, 오늘 끝) - max(시작, 오늘 시작))
오늘 수면시간 = Σ 겹치는 구간
```

**계산은 `now`를 인자로 받는 순수 함수로 만든다.** 함수 안에서 `Date.now()`를
부르면 테스트가 실행 시각에 의존해, 진행 중 수면 케이스를 고정할 수 없다.

- **진행 중인 수면의 종료는 `오늘 끝`이 아니라 `현재 시각`이다.** 아직 오지 않은
  시간을 잤다고 셀 수는 없다.
- **합계는 화면에서 매분 다시 계산한다.** 조회 결과를 숫자 하나로 접어두면
  진행 중인 수면의 기여분이 얼어붙는다. 수면 행 목록을 들고 있다가 `now`로
  다시 더한다. 기존 1분 타이머를 쓰므로 DB를 매분 조회하지 않는다.
- **겹치는 수면이 하나도 없으면 `0시간`이 아니라 `기록 없음`이다.**
  수유량 규칙과 같다 — 안 잔 것과 기록하지 않은 것은 다르다.
  기록이 있는데 합계가 짧으면 `1분 미만`으로 구분해 쓴다.

진행 중인 수면은 정의상 항상 오늘과 겹치므로, 오늘 겹치는 수면 목록에서
종료가 비어 있는 행을 골라 쓰면 된다. 별도 조회가 필요 없다.

- [x] 자정을 넘긴 수면이 오늘 몫만 집계된다
- [x] 진행 중인 수면이 1분마다 반영된다
- [x] `calculateSleepDuration` 경계 8종 단위 테스트

#### 카드 배치

카드가 늘어 스크롤 경계에서 잘려 보인다. 2×2 그리드로 묶어 일반적인 기기에서
한 화면에 들어오게 한다. **`ScrollView`는 유지한다** — 작은 화면이나 큰 글꼴
설정에서는 여전히 넘친다.

#### 단위 테스트

구간 자르기는 지금까지 만든 것 중 경계 조건이 가장 많다. 이 순수 함수 하나만
테스트한다. 컴포넌트 테스트·스냅샷·커버리지 설정은 하지 않는다.

검사 대상: 하루 안에 들어오는 수면 / 전날 시작 / 다음 날 종료 / 하루 전체를
덮는 수면 / 진행 중 / 경계에서 안 겹침 / 여러 수면 합계.

테스트 파일은 `src/app` 밖에 둔다. 그곳은 라우터 루트라 파일이 그대로 라우트가 된다.

**Today 요약 카드까지가 V1이다. 별도 Statistics 화면은 V1.1.**

같은 숫자를 화면만 바꿔 다시 배치하는 것은 값을 하지 않는다. 별도 화면의 의미는
7일 추이·날짜별 비교·평균 수유 간격·일별 수면시간 그래프가 붙을 때 생기고, 그건 V1.1이다.
포트폴리오 관점은 README에 "SQLite 범위 조회와 순수 구간 계산으로 오늘 요약을
산출한다"고 쓰면 충족된다.

### 5단계 — 설정과 마감

#### 5-1. 설정 저장

아이 이름·생년월일, 앱 정보. 설정 탭이 새로 생긴다.

**생년월일은 이 프로젝트에서 처음으로 epoch가 아닌 값이다.** 달력 날짜라
`YYYY-MM-DD` `TEXT`로 저장한다. 기존 `todayRange`·`formatDay`는 전부 epoch
기준이므로 이 값에 그대로 쓰면 안 된다.

키-값 테이블이 아니라 **단일 행 테이블**에 이름과 생년월일을 각각의 컬럼으로
둔다. 타입과 의미가 스키마에 그대로 드러나기 때문이다. 여러 아이 확장과는
무관하다 — 그건 세 기록 테이블 전부에 `baby_id`가 붙어야 하는 별개의 작업이다.

정확한 DDL은 `src/db/migrations.ts`에만 둔다. 중복 문서화하면 코드와 갈라진다.

완료 기준: 이름·생년월일을 저장하고 앱을 재시작해도 남는다.
Today 상단에 아이 이름이 보인다.

**일령("생후 32일")은 넣지 않는다.** 출생 당일을 0일로 셀지 1일로 셀지
결정과 테스트가 따라붙는다. V1.1로 미룬다.

#### 5-2. 사용성 점검

키보드 대응 / 접근성 라벨 / 큰 터치 영역 / 빈 화면 안내.

**키보드는 실기기에서 실제로 무엇을 가리는지 먼저 확인하고, 가리는 화면에만
대응한다.** Android에서 `KeyboardAvoidingView`는 `behavior`가 없으면 사실상
아무 일도 하지 않는다. 설정 화면에 들어 있는 것도 마찬가지다.

리뷰에서 나온 세부 항목:

- 아이 이름에 `maxLength={20}`, Today 인사문에 `numberOfLines={1}`.
  긴 이름이 `마지막 수유` 카드를 화면 밖으로 밀어낸다. 20은 시작값이고
  실기기에서 긴 이름을 넣어보고 조정한다. `numberOfLines={1}`은 기본
  `ellipsizeMode="tail"`이라 말줄임이 자동으로 붙는다.
- 설정 저장 연타 방지. 다만 같은 값 UPSERT라 데이터는 망가지지 않고 알림만
  겹친다 — 수면 종료 연타와 심각도가 다르다.
- 생년월일 버튼의 접근성 라벨에 **현재 값을 포함**한다. 라벨을 명시하면
  자식 `Text`의 날짜가 낭독에서 빠져, 라벨이 없느니만 못해진다.
  수유·기저귀·수면 폼의 날짜·시각 칩에는 라벨도 `accessibilityRole`도 없다.
  값은 자식 `Text`로 낭독되겠지만 버튼이라는 것과 조작 방법은 전달되지 않을
  수 있다. **코드만 보고 판단하지 말고 TalkBack으로 한 번 통과시켜 본다.**
- 로딩 중 비활성 상태가 눈에 보이는지, TalkBack이 비활성을 읽는지 확인한다.
- Records 빈 화면에 다음에 무엇을 하면 되는지 안내한다.

완료 기준: TalkBack으로 주요 흐름을 통과할 수 있다. 키보드가 입력 요소를
가리지 않는다. 빈 화면이 무엇을 하면 되는지 알려준다.

#### 5-3. 디자인 마감

카드·폼 스타일 중복을 **정말 합칠지 이 단계에서 판단한다.** 설정 폼까지
만들고 나서 보는 편이 정확하다. Today 카드가 스크롤 경계에서 잘려 보이는 것도
같이 본다.

**하단 고정 수면 버튼이 수면 중에는 정보 패널로 바뀐다.**

지금은 어두운 `수면 중` 카드와 주황 종료 버튼이 따로 떠서, 수면 중일 때만
카드 그리드가 통째로 밀린다. 새 요소를 추가하지 않고 **하단 같은 자리의 버튼이
상태에 따라 모습을 바꾼다.**

패널에는 시작 시각·경과 시간·안내가 들어가므로 버튼보다 내용이 많다.
높이를 어떻게 다룰지는 두 가지다.

- **바깥 높이를 패널 기준으로 고정**하고 안쪽 내용만 버튼 ↔ 패널로 바꾼다.
  상태가 바뀌어도 아무것도 움직이지 않는다. 대신 평상시에 여백이 남는다.
- 높이가 상태에 따라 달라지게 둔다. 시작·종료할 때 한 번 밀리지만 그건
  동작에 대한 반응으로 읽힌다.

**어느 쪽이든 본문 카드 사이에 요소를 끼워 넣지는 않는다.** 지금 거슬리는
원인은 높이 변화가 아니라 `수면 중` 카드가 그리드 한가운데를 차지하는 것이다.
만들어보고 정한다.

```
평상시
┌────────────────────────────┐
│        🌙 수면 시작         │
└────────────────────────────┘

수면 중
┌────────────────────────────┐
│ 🌙 수면 중       1시간 8분   │
│    22:14 시작    탭해 종료   │
└────────────────────────────┘
```

- 본문의 별도 `수면 중` 카드는 **제거한다.**
- `오늘 수면` 요약 카드는 **유지한다.** 진행 중 시간과 오늘 누적은 다른 값이다.
- 패널에 시작 시각, 지금까지 잔 시간, 12시간 이상 안내를 담는다.
- TalkBack에는 상태 전체를 준다 — `수면 중, 1시간 8분, 탭하여 종료`.
- 진행 시간은 기존 1분 타이머로 갱신한다.
- **패널 전체를 누르면 `수면을 종료할까요?` 확인창을 한 번 띄운다.**
  터치 영역이 버튼 하나보다 훨씬 넓어 오터치 위험이 크기 때문이다.
- 화면 전체를 덮는 오버레이나 `Modal`은 쓰지 않는다. 수면 중에도 수유·기저귀를
  기록하고 기록 탭을 볼 수 있어야 한다. 수유·기저귀 버튼과 하단 탭은 그대로다.

**`app.json`의 `userInterfaceStyle`을 `"light"`로 고정할지 정한다.**
네이티브 설정이라 재빌드가 필요하지만, 5-4 뒤에 어차피 preview APK를 새로
만들므로 추가 비용은 없다.
지금은 `"automatic"`인데 JS 화면은 밝은 색을 하드코딩하고 `ThemeProvider`도
없다. 그래서 기기가 다크모드면 **날짜·시각 선택기만 어두운 배경으로 뜬다.**
수동 다크모드는 V1.1이므로 V1에서는 고정하는 편이 일관된다.

삭제 확인 Alert(UI 부수효과를 이름 뒤로 감춤)과 미래 시각 검사(비교 한 줄)는
추출 이득이 작아 **V1에서 공통화하지 않기로 이미 정했다.**

완료 기준: 합칠지 말지 정하고 이유를 이 문서에 남긴다.

#### 5-4. Android 최종 확인

전체 흐름을 처음부터 끝까지 재확인한다. iOS는 이 단계에서 다루지 않는다.

- 수유·기저귀·수면 추가·수정·삭제
- 수면 진행 중 앱 재시작과 종료, 백그라운드 복귀
- 설정 저장과 선택 해제
- 자정 경계 집계
- **새 설치에서 `user_version` 0 → 4 마이그레이션이 한 번에 도는지**
- 기존 데이터가 있는 상태에서 재실행

여기까지 끝나면 `preview` 프로필로 APK를 만들어 Metro 없이 설치형으로
최종 확인한다. `development` 프로필은 dev client가 들어가 Metro가 필요하므로
이 용도에 쓸 수 없다.

### 6단계 — Google Play 출시
아이콘·스플래시 / 실기기 테스트 / 개인정보 처리방침 / 스토어 이미지·설명 /
production build / 내부 테스트 / Android 출시.

README와 에셋 상당수가 아직 `create-expo-app` 기본 템플릿이다. README를
carelog 내용으로 바꾸고, 쓰지 않는 템플릿 에셋과 의존성을 정리한다.

스토어 등록명은 이 단계에서 정한다. `app.json`의 `name`(홈 화면에 뜨는 앱 이름)과
스토어 등록명은 다른 값이고, 전자는 바꾸면 네이티브 재빌드가 필요하다.
앱 식별자 `com.kjw1801.carelog`는 같은 스토어 앱의 업데이트에서 변경할 수 없다.
바꾸면 별개의 앱으로 취급된다.

### 7단계 — iOS 대응

**V1은 Android 단독 출시다.** iOS는 Google Play 출시 이후 별도로 진행한다.

지금까지 iOS에서 한 번도 실행해본 적이 없어 예상되는 작업이 남아 있다.
`DateTimePicker`가 iOS에서는 인라인으로 뜨고, 모달 프레젠테이션 동작도 다르다.

시뮬레이터 빌드는 Apple Developer Program 가입 없이 만들 수 있다.
실기기 서명과 App Store 배포에는 계정이 필요하다.

TestFlight / App Store 심사.
