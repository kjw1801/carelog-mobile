# carelog — 개발 계획

육아 기록 앱. 수유 / 기저귀 / 수면을 빠르게 기록하고 오늘 요약을 본다.

## 개발 원칙: 기능별 세로 완성

화면을 전부 만든 뒤 DB를 붙이지 않는다. **기능 하나가 Today → SQLite → Records → 수정·삭제까지
전부 동작**하게 만든 뒤 다음 기능으로 넘어간다. 난이도 순서상 수유 → 기저귀 → 수면.

각 단계가 끝나면 변경사항 / 실행 방법 / 확인 항목을 보고하고 멈춘다.
사용자가 직접 실행해 확인한 뒤에만 다음 단계로 진행한다.

## 데이터 규칙

### 수유 (V1)

| 필드 | 필수 | 비고 |
|---|---|---|
| 수유 시각 | 필수 | |
| 수유량(ml) | 선택 | |
| 메모 | 선택 | |
| 생성·수정 시각 | 내부 | 사용자에게 노출하지 않음 |

**수유량을 입력하지 않으면 `0`이 아니라 `NULL`로 저장한다.**
`0ml 수유`와 `양을 기록하지 않은 수유`는 의미가 다르다.

집계 표시도 같은 원칙을 따른다. 오늘 수유량이 한 번도 입력되지 않았다면
`총량 0ml`로 보여주지 말고 항목을 숨기거나 `기록 없음`으로 표시한다.

### 시각과 날짜 저장

| 값 | 타입 | 이유 |
|---|---|---|
| 수유 시각 (`occurred_at`) | epoch milliseconds `INTEGER` | |
| 수면 시작·종료 | epoch milliseconds `INTEGER` | |
| 생성·수정 시각 | epoch milliseconds `INTEGER` | |
| 아이 생년월일 | `YYYY-MM-DD` `TEXT` | 특정 순간이 아니라 달력상의 날짜다. epoch로 저장하면 시간대가 바뀔 때 날짜가 밀린다 |

SQLite는 ISO 8601 문자열도 정상 지원한다. epoch milliseconds를 고르는 이유는 그것이
옳아서가 아니라, 이 앱이 정렬·범위 검색·두 시각의 차이 계산을 많이 하고
JS와 왕복 변환이 없기 때문이다.

주의: SQLite의 `unixepoch` 계열 함수는 **초 단위**다. 밀리초 값을 그대로 넘기면 안 된다.
날짜 경계는 JavaScript에서 계산하고 숫자 범위로 조회한다.

```sql
WHERE occurred_at >= ? AND occurred_at < ?
```

`occurred_at`에는 인덱스를 건다. 모든 조회가 이 컬럼의 범위 검색이다.

### "오늘"의 경계

**기기 현지 시간 기준 00:00 이상, 다음 날 00:00 미만.**

새벽 수유를 전날 육아 주기에 포함하는 방식도 가능하지만 "하루 시작 시각 설정"이라는
새 기능이 필요해진다. V1에는 과하다.

끝 시각을 `시작 + 86,400,000ms`로 계산하지 않는다. 서머타임 지역에서는 하루가 항상
24시간이 아니다. 현지 달력으로 오늘 자정과 다음 날 자정을 각각 만든 뒤 epoch로 변환한다.
(한국은 서머타임이 없어 실제로 깨지지 않지만, 비용이 없으므로 처음부터 맞게 쓴다.)

### 경과 시간 갱신

"마지막 수유 1시간 24분 전"은 화면을 열어둔 동안 멈춰 있으면 안 된다.

- 화면 표시 중 1분마다 갱신한다
- 백그라운드에서 foreground로 돌아오면 즉시 갱신한다
- 화면을 벗어나면 타이머를 정리한다
- 갱신할 때마다 SQLite를 다시 조회하지 않는다. 마지막 수유 시각만 들고 현재 시각만 갱신한다

### 입력 검증

- **빈 문자열 판정과 숫자 변환을 분리한다.** `Number('')`는 `0`이므로
  `Number(input) || null` 같은 코드는 빈 입력과 진짜 `0` 입력을 둘 다 `null`로 만든다.
- 미래 시각은 저장하지 않는다. 허용하면 "마지막 수유 -5분 전"이 나온다.

### Today 화면 표시 예

```
마지막 수유      1시간 24분 전
오늘 수유        5회
입력된 수유량    220ml
```

## 단계

### 0단계 — 프로젝트 기반
- [x] Expo SDK 57 + TypeScript + Expo Router
- [x] 빈 Today / Records 화면과 탭 이동
- [x] Android 실기기 실행 및 탭 이동 확인
- [x] Root Stack + `(tabs)` 구조 (모달을 띄울 자리 확보)

완료 기준: 빈 Today와 Records 화면을 Android에서 오갈 수 있다.

### 1단계 — 수유 기능 하나 완성
SQLite 초기화 / 기록 추가 / Today의 마지막 수유·오늘 횟수 /
Records 시간순 목록 / 수정·삭제 / 앱 재시작 후에도 유지.

완료 기준: 수유 기록만으로 실제 하루를 써볼 수 있다.

**이 단계를 Expo Go에서 확인한 직후 development build를 구성한다.**
출시용 프로젝트에는 development build가 권장되므로 끝까지 미루지 않는다.

### 2단계 — 기저귀
소변·대변·둘 다 / 기록 시각 / Today 횟수 / Records 통합 타임라인 / 수정·삭제.
수유의 CRUD 구조를 재사용하되 억지로 범용 프레임워크를 만들지 않는다.

완료 기준: 수유와 기저귀가 하나의 타임라인에 시간순으로 나온다.

### 3단계 — 수면 (가장 복잡, 마지막)
시작·종료 / 진행 중인 수면은 하나만 허용 / 앱 종료해도 진행 상태 유지 /
시작·종료 시각 수정 / 잘못 시작한 수면 삭제 / 자정을 넘는 수면 처리.

완료 기준: 밤에 수면을 시작하고 앱을 종료한 뒤, 다음 날 열어 정상 종료할 수 있다.

### 4단계 — Today 요약과 통계
오늘 수유 횟수 / 입력된 수유량 합계 / 오늘 수면시간 / 오늘 기저귀 횟수 /
마지막 수유 후 경과 시간 / 카드 UI 정리.

**Today 요약 카드까지가 V1이다. 별도 Statistics 화면은 V1.1.**

같은 숫자를 화면만 바꿔 다시 배치하는 것은 값을 하지 않는다. 별도 화면의 의미는
7일 추이·날짜별 비교·평균 수유 간격·일별 수면시간 그래프가 붙을 때 생기고, 그건 V1.1이다.
포트폴리오 관점은 README에 "SQLite 집계 쿼리로 오늘 요약을 계산한다"고 쓰면 충족된다.

### 5단계 — 설정과 마감
아이 이름·생년월일 / 앱 정보 / 빈 화면 / 삭제 확인 / 입력값 검증 /
큰 터치 영역 / 키보드 대응 / 접근성 라벨 / Android·iOS 기본 확인.

### 6단계 — 출시 준비
아이콘·스플래시 / 실기기 테스트 / 개인정보 처리방침 / 스토어 이미지·설명 /
production build / 내부 테스트 / Android 출시 / iOS TestFlight.

## 범위

**V1 필수** — 수유·수면·기저귀, 빠른 기록, 날짜별 기록 목록, 추가·수정·삭제,
SQLite 저장, 오늘 요약, 아이 이름·생년월일, Android/iOS 기본 동작.

**V1.1 이후** — 별도 Statistics 화면, 7일 추이 그래프, 백업·가져오기, 수동 다크모드, 수유 타이머와 좌우 구분,
유축, 알림, 여러 아이, 클라우드 동기화.

**V1에 넣지 않는다** — 왼쪽/오른쪽 가슴 구분, 수유 타이머, 수유 지속시간,
직수/유축/분유 종류, 한 번의 수유에서 좌우 전환, 수유 알림.
`언제 먹었는지`와 `오늘 몇 번 먹었는지`만으로 충분히 쓸 수 있다.
